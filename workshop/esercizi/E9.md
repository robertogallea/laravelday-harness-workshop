# E9 — Trace events: dare un nome al fallimento (opzionale)

**Blocco:** B4 · **Durata:** 15' · **Livello MVH:** L4 (osservabilità), L6
**Ingresso:** `cp-08` · **Uscita:** `cp-09` (la versione consegnata, tag `laravelday-2026`)
**In aula:** non è in agenda. Si fa a casa, o in aula se dopo E8 avanza tempo; la soluzione è in `cp-09`.

## Obiettivo

Ogni hook scrive una riga in `.harness/runs/<run>/trace.jsonl`: chi ha negato cosa, che cosa ha detto il post-edit, com'è andato lo stop. Oggi ogni riga ha `"class": "unclassified"`. Un trace senza classi si legge solo a occhio; con le classi si contano i fallimenti per tipo e si risponde a domande vere: quante volte l'agente ha provato a toccare un file protetto? Il post-edit trova più errori di tipo o di stile? La regola di L-003 è mai scattata, o è un candidato al decay?

## Da dove parti

- `.harness/rules/classify.php`: la policy, con una funzione che oggi restituisce `'unclassified'`. Il commento elenca già metà delle classi.
- `.harness/lib/harness.php`: l'impianto. `trace()` scrive la riga e chiama la tua funzione per il campo `class`; se la funzione lancia un'eccezione, la riga resta `unclassified` (il trace non deve mai rompere un hook).
- `.harness/fixtures/classify/`: 7 fixture, 108 eventi. Cinque raccolgono i casi per hook; due sono i trace veri di una run 2 di Claude e di una di Codex, ridotti ai campi che servono.

## Cosa fare

**TODO `classify(array $event): string`**: una classe per ogni riga di trace. `$event['event']` dice da che hook viene; il resto dipende dall'evento.

| Evento | Classe |
|---|---|
| `*.error` (qualunque hook) | `hook_error` |
| `pre_tool.denied` con `rule` `env.access` o `task.must-not-change` | `protected_file` |
| `pre_tool.denied` con `rule` `migration.*` | `destructive_migration` |
| `pre_tool.denied` con `rule` `task.out-of-scope` | `scope_violation` |
| `pre_tool.denied` con `rule` `task.no-contract` | `no_contract` |
| `pre_tool.denied` con `rule` `task.self-approval` | `self_approval` |
| `pre_tool.denied` con `rule` `harness.tamper` | `harness_tamper` |
| `pre_tool.denied` con un'altra regola (la tua di L-003, per esempio) | `policy_block` |
| `post_edit.checked` con `phpstan_errors` > 0 | `static_analysis` |
| `post_edit.checked` con `pint_fixed` non vuoto | `lint` |
| `post_edit.checked` con `skipped` non vuoto (uno strumento non è partito) | `env_unavailable` |
| `stop.blocked` | la prima di `classes` (`test_failure`, `missing_evidence`, …: le classi del receipt) |
| `stop.escalated` | `budget_exhausted` |
| tutto il resto (`pre_tool.allowed`, `session.started`, `stop.passed`, `stop.waiting`, …) | `none` |

Due regole in più:

1. **L'ordine nel post-edit:** PHPStan prima di Pint, Pint prima degli strumenti saltati. Un file con un errore di tipo e una riformattazione è `static_analysis`.
2. **Mai `unclassified`, e mai un warning:** una riga può non avere `rule`, `classes` o `phpstan_errors` (un evento nuovo, una regola appena scritta). Usa `??`. Un deny che non conosci è `policy_block`, uno stop rosso senza `classes` anche.

## Verifica

```bash
php .harness/bin/verify E9
```

Rigioca i 108 eventi delle fixture e, per ogni fixture sbagliata, mostra fino a tre eventi con la classe attesa e quella ottenuta, più il `_why`. Poi passa alla funzione nove righe minime (una regola che non esiste, campi assenti, un hook nuovo): nessuna deve restare `unclassified` o produrre un warning. Si parte da 0/7.

Poi guarda un trace vero, se hai fatto la run 2. Le classi si calcolano mentre l'hook scrive, quindi il trace della run 2 resta `unclassified`: ricalcolalo con la tua funzione.

```bash
php -r '$f = require ".harness/rules/classify.php";
  foreach (glob("workshop/runs/run-2/trace.jsonl") as $t) foreach (file($t) as $l) { $e = json_decode($l, true); echo $f($e), "  ", $e["event"], PHP_EOL; }' | sort | uniq -c | sort -rn
```
